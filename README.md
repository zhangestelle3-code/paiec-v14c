Frozen predictor submitted by Xinyue Zhang for PAIEC 2026, submission 1018221. This repository contains the original prediction code and executable historical local diagnostics.

# PAIEC 61 reproduction guide

## 1 Official submission results

V14C submission 1018221 is recorded as formative Brier ALC 0.146273; identical-code repeat 1029961 is recorded as 0.199613. See official_runs.json for the exact evidence status. frozen_submission.zip preserves the supplied original ZIP; its model.py matches this directory's model.py. These are historical official scores, not scores generated by the local scripts. Independently sampled formative reruns need not return the same value. No private labels or anonymous identity tables are distributed.

## 2 Check the package and reproduce aggregate tables without raw data

Open a terminal in the repository root directory. Python 3.12 was used for validation. This mode uses only the standard library:

```bash
python reproduce.py --mode audit
```

This verifies the frozen code and packaged loss-table hashes, runs the synthetic interface checks, recomputes ALC arithmetic, group-bootstrap intervals and tables from archived loss rows, and exports results under run_results. It does not rerun historical predictions and does not establish original-data provenance.

Outputs: main_table.csv matches the three-control table in paper Section 4.2; budget_table.csv adds six-budget detail; benchmark_table.csv adds domain detail; audit_results.json includes conditional paired intervals. report.json records scope, environment, hashes and pass/fail information. interface.log records the synthetic checks.

## 3 Regenerate predictions from the exact historical input

```bash
python -m pip install -r requirements_reproduction.txt
python reproduce.py --mode full --db /absolute/path/benchmark_data.sqlite
```

The input database is not shipped in this release. The author recovered it from the earlier AI prediction-tool archive. data_input_manifest.json specifies the expected fingerprint, selection protocol and remaining provenance gap. An external reader with only this release can run audit mode, but cannot currently regenerate original predictions without separately obtaining that exact input. No unverified public download link is supplied, and a current official download is not assumed byte-equivalent to this historical compilation.

Full mode runs the original recovered-input reproduction script, checks all regenerated budget losses and ALC against archived rows with tolerance 1e-10, runs real-data function parity checks, and exports the same table formats using regenerated rows. original-input results and logs are under run_results/full. Both seed sets reuse the same five benchmark collections. This is not a held-out-benchmark test or the official scoring harness. Use a different --out path to retain a separate run. Allow several minutes depending on the computer; timing is recorded rather than guaranteed.

## 5 Release boundary

Exact upstream data release alignment and external availability of the historical database remain unresolved. Prediction code is unchanged. Model matching omits some configuration fields; the bounded correction does not guarantee lower error. See the paper for limitations and AI assistance disclosure. ## 6 Executed validation for this update

Both audit and full modes passed from a fresh directory on Python 3.12.14. Full mode regenerated 2210 seed-group rows and matched every archived budget loss and ALC exactly; 376 function parity checks passed. The two modes produced identical main tables. A validated execution summary is retained in VALIDATION.md. This validates the supplied execution instructions on the author-held input, without resolving external access to that input.
